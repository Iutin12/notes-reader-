# Нотера

Нотера — локальное веб-приложение для чтения и поэтапного проигрывания
фортепианных партитур. Оно распознаёт печатные ноты из PDF через Audiveris,
открывает MusicXML, MXL и MIDI, строит независимую временную шкалу событий,
воспроизводит ноты через Web Audio API и показывает текущую позицию.

## Быстрый запуск

### Docker Compose

```bash
cp .env.example .env
docker compose up --build
```

Откройте [http://localhost:3000](http://localhost:3000).

Первый запуск загружает официальный пакет Audiveris 5.10.2 размером около
70 МБ и собирает три контейнера. Рекомендуется не менее 6 ГБ свободной
оперативной памяти. Дальнейшие запуски используют Docker-кеш.

Контейнер Audiveris выпускается для `linux/amd64`. На компьютере с Apple
Silicon Docker Desktop автоматически использует эмуляцию; распознавание будет
медленнее.

Проверка состояния:

```bash
docker compose ps
docker compose logs -f omr
```

### Локальная разработка

Для интерфейса нужен Node.js 24 и pnpm. PDF-распознавание при обычном `pnpm dev`
недоступно, если отдельно не запущены `omr` и reverse proxy, поэтому для полного
сценария используйте Docker Compose.

```bash
pnpm install
pnpm dev
```

### Установщики для macOS и Windows

Установщик открывает Нотеру как обычное настольное приложение. Для работы
распознавания PDF на компьютере всё равно необходим
[Docker Desktop](https://www.docker.com/products/docker-desktop/): приложение
запускает локальные контейнеры само и не передаёт партитуры сторонним сервисам.
При первом запуске Docker соберёт сервисы и загрузит Audiveris, поэтому он может
занять несколько минут. Загруженные произведения сохраняются в Docker volume.

Собрать установщики из исходного кода:

```bash
pnpm install
pnpm desktop:build:mac # macOS: .dmg
pnpm desktop:build:win # Windows: .exe (NSIS)
```

Готовые файлы появляются в папке `release/`. Без сертификата Apple или Microsoft
система может показать стандартное предупреждение для неподписанного приложения.

## Что работает

- загрузка PDF, `.musicxml`, `.xml`, `.mxl`, `.mid` и `.midi`;
- проверка расширения, MIME и сигнатуры PDF;
- ограничение PDF до 50 МБ и 40 страниц через конфигурацию;
- реальная подготовка PDF: Poppler 300 DPI, оттенки серого, выравнивание,
  обрезка полей и повышение контраста;
- изолированное фоновое OMR-распознавание Audiveris 5.10.2;
- реальные этапы обработки, миниатюры страниц, отмена и повтор задачи;
- проверка и извлечение MusicXML из результата Audiveris;
- автоматическое открытие и проигрывание распознанной партитуры;
- серверное хранение PDF, проекта Audiveris и результата в Docker volume;
- демонстрационная двухголосная партитура CC0;
- отрисовка MusicXML через OpenSheetMusicDisplay;
- импорт MIDI во внутреннюю временную шкалу и отображение piano-roll;
- синтез нот и аккордов через Web Audio API;
- воспроизведение, пауза, остановка, перемотка и переход по событиям;
- скорости от 25% до 200%, громкость и транспонирование ±12 полутонов;
- режимы «всё произведение», «по одной ноте», «по тактам» и «фрагмент»;
- выбор партий, диапазона тактов и циклического повтора;
- метроном, отсчёт перед стартом, названия нот и автопрокрутка;
- горячие клавиши `Пробел`, `←`, `→`, `R`, `M`, `Esc`;
- светлая и тёмная темы;
- сохранение последних MusicXML-партитур на текущем устройстве;
- экспорт исходного MusicXML.

AudioContext создаётся и запускается только после нажатия пользователем кнопки
воспроизведения. При паузе, остановке и перемотке все активные генераторы
останавливаются, чтобы не оставалось зависших нот.

## Архитектура

- `app/page.tsx` — пользовательские сценарии, загрузка файлов и экран
  проигрывателя;
- `lib/music.ts` — внутренняя модель, MusicXML-парсер, фильтрация диапазонов и
  расчёт времени;
- `lib/audio.ts` — изолированный Web Audio-синтезатор;
- `omr-service/app/main.py` — API задач, валидация PDF, подготовка страниц,
  запуск Audiveris, хранение и выдача MusicXML;
- `omr-service/Dockerfile` — Audiveris 5.10.2, Poppler, ImageMagick,
  Tesseract и изолированный непривилегированный пользователь;
- `nginx/notera.conf` — единая точка входа: интерфейс и `/api/omr/*`;
- OpenSheetMusicDisplay отвечает только за визуальную партитуру;
- временная шкала не зависит от SVG/DOM и остаётся источником позиции,
  воспроизведения и фильтрации партий;
- `public/demo.musicxml` — специально созданный демонстрационный файл с
  лицензией CC0.

## Проверки

```bash
pnpm lint
pnpm typecheck
pnpm test
pnpm build
pnpm test:integration
docker compose config
```

Модульные тесты проверяют расчёт времени и скорости, аккорды, паузы, выбор
тактов и диапазонов, партии и названия нот. Интеграционный тест собирает
production-версию и проверяет серверную отдачу основного экрана.

Тесты API OMR:

```bash
python3 -m venv .venv
. .venv/bin/activate
pip install -r omr-service/requirements-dev.txt
pytest omr-service/tests
```

## Данные и удаление

Файлы задач сохраняются в Docker volume `omr-data`. Отмена останавливает
Audiveris. Кнопка удаления для завершённой или ошибочной задачи удаляет PDF,
миниатюры, `.omr`, журналы и MusicXML этой задачи.

Удалить контейнеры, сеть и все загруженные партитуры:

```bash
docker compose down -v
```

## Известные ограничения первой итерации

- Сохранение MusicXML выполняется в локальном хранилище браузера; серверное
  хранение PDF и результатов доступно в Docker volume, но библиотека
  произведений пока не синхронизируется между разными браузерами.
- Качество PDF-распознавания зависит от качества печати и скана. Рукописные
  ноты и сложные оркестровые партитуры не гарантируются.
- Если Audiveris разделит книгу на несколько независимых movements, первая
  итерация открывает первый полученный MXL.
- MIDI воспроизводится и показывается как piano-roll, но не преобразуется в
  нотную гравировку MusicXML.
- Редактор распознанных нот и экспорт MIDI относятся к следующей итерации.
- Синтезатор намеренно лёгкий и офлайн; это не многослойный фортепианный
  soundfont.
- Полная семантика лиг, смен темпа внутри произведения, сложных многоголосных
  перемещений `backup/forward` и орнаментов требует расширения парсера.

## Настройки OMR

Параметры находятся в `.env`:

- `MAX_UPLOAD_BYTES` — максимальный размер PDF;
- `MAX_PDF_PAGES` — максимальное число страниц;
- `OMR_TIMEOUT_SECONDS` — время одной задачи;
- `OMR_MEMORY_LIMIT` и `OMR_CPU_LIMIT` — ресурсы контейнера;
- `JAVA_TOOL_OPTIONS` — размер heap Audiveris.

Не задавайте JVM heap больше лимита памяти контейнера.
